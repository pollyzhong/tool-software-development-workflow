# 工具软件开发工作流

面向用 Codex 开发网页工具、微信小程序、桌面应用或 2D/3D 编辑器的人。它把零散的想法整理成可执行的批次，先跑通一个完整流程，再按需要加功能，减少返工和反复沟通。

## 它怎么工作

1. **先问关键问题。** 谁在哪个平台用？第一版要完成什么？哪些数据和行为不能丢？只问会影响范围或架构的问题，不重复问已知信息。
2. **把功能分成三类。** 先定不容易改的基础，例如数据结构、单位和旧存档兼容；MVP 只跑通一条能上手的流程；已经有扩展空间的功能后加。拿不准的技术风险先提出最小验证方案，不直接押注新框架。
3. **入批和开工分开确认。** 讨论中的需求先待确认。确认入批不等于开工；列出完整清单并获准开工后，逐项完成这一批，不只改最后一条，也不自行把新想法加进来。
4. **按清单交付。** 说明每一项改了什么、在哪里体验、还有哪些未完成。测试、构建、预览和发布单独确认。

## 在 Codex 中使用

将本仓库目录放到 Codex 的技能目录中，例如 `~/.agents/skills/tool-software-development-workflow/`，保留目录结构，确保 `SKILL.md` 在该目录顶层。在新的 Codex 对话中输入：

```text
使用 $tool-software-development-workflow。
我要做一个给租客用的户型编辑器，主要在手机上使用。
先问会影响架构的关键问题，再给我「先定 / MVP / 后加」清单。
现在不写代码，等我确认完整批次再开工。
```

例如，户型编辑器可以先定平面与 3D 共用的方案数据、尺寸单位和存档规则。第一版只做一个房间、一扇门和一件家具，跑通编辑、切换视图、保存再打开。家具素材、配色和工具栏样式可以后加。
