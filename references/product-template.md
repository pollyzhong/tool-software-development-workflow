# Product Template

Use this structure for `PRODUCT.md` when the repository has no equivalent.

```markdown
# Product

## Purpose

One sentence describing the user, job, and outcome.

## Primary Users

- User:
- Context:
- Pain:
- Success signal:

## Core Workflow

1. Entry
2. Create/import
3. Edit
4. Validate
5. Save/share/export

## Release Scope

### Must Have

- Feature with observable outcome

### Next

- Feature that improves the core workflow

### Later

- Optional or expensive feature

## Non-Goals

- Explicitly excluded behavior

## Product Rules

- Rule that must remain true across implementations

## Success Criteria

- User-facing measurable result
```

Keep this document product-oriented. Put implementation details in `ARCHITECTURE.md`.
